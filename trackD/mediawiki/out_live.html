A neural network computed by the page renderer

This file is plain MediaWiki markup (README.mediawiki). There is no JavaScript, no GitHub Action and no program of ours: every cell marked live below is evaluated by the markup renderer's parser functions (#expr, #ifeq, #switch) when this page is rendered. The model is a character model: given two characters it predicts the next one with a 12-input, 12-hidden-unit (ReLU), 5-output-bit integer network (32 symbols; ␣ = space). Trained offline (numpy/torch) on 175 characters of this project's own README text; trained exact-match on that text: 64%.

3. What is and is not computed by the renderer

  • Computed live: every multiply-accumulate of both layers, the ReLU, the sign test of each output bit, and the bit-string to character decode.
  • Fixed in the text: the trained integer weights (as literals), the choice of which two input characters each row uses, and the embedding gather (the two embedding vectors for the row's input are written as literals; there is no variable or loop to look them up).
  • A README has no viewer input, so each row is a constant expression; the demonstration is that a real network forward pass is evaluated by the renderer, not that it is interactive.
