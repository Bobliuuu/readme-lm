# issue-flow: README-LM issue flow in a logged-in Chrome

Real screenshots, held about 1.6 s each (no interpolated or synthetic frames).

Steps shown, in order:
1. github.com/Bobliuuu/readme-lm, repo page.
2. Scrolled to "Try it now" (real).
3. Clicked the `qa:` "open one" link from the README (real click). The new-issue form opened with the title `qa: example text` and the body prefilled.
4. Title changed to `qa: where does jerry work` (real typing).
5. Issue #11 (`qa: where does jerry work`) with the github-actions bot reply image, "Jerry works on data infrastructure at Shopify.", and the issue closed as completed.
6. github.com/Bobliuuu profile animation (looping typing animation).

Provenance:
- The issue was really created (Bobliuuu/readme-lm#11) during a first live run, and the Action replied and closed it within about 20 s. The first run's recorded GIF could not be saved to disk (the extension's download did not land), so this file was rebuilt from a second pass.
- In the second pass, steps 1-4 were repeated for real but Create was NOT clicked (only one issue was authorized). Steps 5-6 show the real, already existing issue #11 and the live profile.
- So the Create click and the live wait for the Action are not in these frames; they happened in the first run only.
- The profile frames show the animation mid-loop; the answer text is not visible in them.
